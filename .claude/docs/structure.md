## Script Load Order (Astro build output)
1. `<style is:inline>` — Critical CSS inline in `<head>` (reset, layout, tokens)
2. Inline `<script>` in `<head>` — Trusted Types policy (passthrough)
3. Inline `<script>` in `<head>` — Service-worker/cache cleanup
4. Inline `<script>` in `<head>` — Build-etag poller (`fgo_build_etag`, "new version available" banner)
5. Inline `<script>` in `<head>` — Tab init (reads localStorage, sets `data-tab`, `data-bond-quest` / `data-bond-custom` for zero-CLS pre-paint quest row display, preloads LCP images; Bond Gain CE preload list = **first row only** — first servants ordered by collectionNo matching `CEFilterApp._getCols()` — high-priority image preloads outrank tab's own chunks, 39-link list pushed LCP 1684 ms to 2944 ms under 1.6 Mbps / CPU 4x. `plain` skips list when saved `cePicks` or Servant Select sub-tab renders a different first page)
6. `<script type="module">` — Astro entry chunk (imports main-entry + shared chunks eager)
7. Lazy chunks via dynamic `import()` on tab switch (bond-lazy, event-lazy)
8. Web Worker (`ce-match-worker.js`) spawned by CEFilterApp for first trait match compute

## CSS
- Browser sees only the single `<style is:inline>` block in `BaseLayout.astro` (tokens + full styles). Astro emits no `.css` file, `index.astro` imports no stylesheet
- No second copy to keep in step: `src/styles/` (`global.css`, `critical.css`) deleted 2026-11-04, its rules drifted out of shipped block; `npm run lint:css` / stylelint went with it. Rule not in that inline block does not exist
- Zero web fonts: uses native system font stacks (`system-ui`, `ui-monospace`) with no `@font-face` or preload overhead

## JS Loading (Astro 7 / Vite 8 + Rolldown `codeSplitting.groups`)
- `main-entry`: Bond Gain CE tab code, eager
- `data-chunk`: shared data module
- `ce-filter-chunk`: Bond Gain CE logic
- `tab-navigator-chunk`: tab switch
- `selectors-chunk`: modal/picker components
- Lazy: `bond-lazy` (Bond tab), `event-lazy` (Event tab: tier calculator + EventPlanner + EventShopModal + EVENT_SHOP_DATA + Select Event wiring + farm hydration) — via `import()` on first visit
- Worker: `ce-match-worker` — own chunk for Web Worker

## Architecture (3 layers)
- **Layer 1 — Domain** (`domain.js`): Schema, Validator, Calculator, BondLevelCalculator, TraitMatcher, ServantComboCalculator, SlotCEs, ServantFilters, ServantSort. Pure logic, no DOM
- **Layer 2 — Application** (`state.js`, `*-app.js`, `ce-servant-select.js`): StateManager, Persistence, App, BondApp, CEFilterApp, ServantSelect, CEFilterStore; state + orchestration; circular deps via callback injection in `main.js`
- **Layer 3 — Presentation** (`presentation.js`, `selectors.js`, `filter-sections.js`, `tab-navigator.js`): DOMFactory, CollapsibleFactory, FilterSections, FilterModalController, ComboCardRenderer, selectors, DOM only; selectors get callbacks at `open()`/`init()`

`CEServantOverlap` — Layer 3 modal in `selectors.js`; `_getCEMatches` callback; 50ms debounce.
Selector callback: `onSelect(slotIndex, id, ascensionOrOptionId)` — always 3 args.
Domain rule: fn touching `document` belongs in Layer 3.

## Bond Gain CE UI (top→bottom, second card)
Servants card: search bar (top) → controls row (Filter button + Sort By / Sort Order) → top pagination → results grid → bottom pagination. "Filter" opens "Filter Settings" modal: 8 labelled sections — rarity, class, class group, alignment (Lawful/Neutral/Chaotic), alignment (Good/Balanced/Evil/Other), sub-attribute, gender, CE match count — each centred label over centred chips, card's own 2px `--border` separator between, one scrolling column. `src/scripts/filter-sections.js` (`FilterSections`) builds every chip row; row lists in `constants.js`, matching rules in `ServantFilters` (`domain.js`).

Servant picker modal (`#servantModal`) repeats that shape for its grid — search bar → Filter button + Sort By / Sort Order → picker grid, class + rarity in nested `#servantFilterModal` — one comparator orders both lists: `ServantSort` (`domain.js`).

Sub-tabs (`#cefilterSubtabs`, top-right of controls card) swap one panel per card: `ce` = Craft Essence Select (chain above), `servant` = Servant Select (defaults to evaluating all servants when 0 picks, 5-row pagination (`cols * 5`), Add Servant + Clear all (N) buttons and chips → shared-CE cards in `#cefilterComboResults`, rendered by `ce-servant-select.js`; pick list and active `subTab` persist across refresh).

## Adding Features
- 3-layer pattern: domain → app state → presentation
- New modules in `src/scripts/`; Astro auto-bundles + code-splits
- New modals: callback pattern from `selectors.js`
- New data fields: whitelist in `CEList` IIFE in `src/scripts/data.js`
- Heavy DOM renders: batch with `DocumentFragment`
- Below-fold images: `DOMFactory.createLazyImg()`
- After changes: `npm run build` (or push to main for CI build)

## Responsive CSS
- Breakpoints: 580 / 760 / 940 / 1120 px
- Container max-width: 400 / 580 / 760 / 940 / 1120 px
- `.card-inner` margin: 6.4 / 12.4 / 18.4 / 24.4 / 30.4 px
- `--portrait-lg: 96px` all breakpoints
- `:hover` always in `@media (hover: hover)`; `:active` after, for touch
- New grids: mobile override at matching breakpoint

## Git
- `main` — production (GitHub Pages)

- `feat/*` — features
- Flow: feat → develop → main → push

- GitHub Pages source: "GitHub Actions" (not branch-based)
- `dist/` gitignored — CI generates build output

## Image Conventions
- WebP only
- Portraits: `public/servants/{atlasId}/{stage}.webp`
- CEs: `public/craft_essences/{atlasId}.webp` (bordered 142×155, one size fits all displays)
- Icons: `public/icons/*.webp`, `public/icons/{category}/*.webp`
- Size 2× render dims for Retina (e.g. 112×120 for 56×60 container)
